## Iteration contract

1. Read this file, the current compatibility backlog, `PROGRESS.md`, and the relevant code before selecting the next unfinished capability.
2. Select bounded independent implementation slices. Use the Workflow tool with explicit file ownership; prevent parallel writes to shared CLI registration, progress, or generated artifacts. Read the workflow-authoring skill before authoring orchestration scripts.
3. Implement and test real behavior. Add regression tests and exercise CLI entry points where applicable. Review correctness, refusal paths, generated-code usability, and compatibility claims independently.
4. Integrate the slice. Update the feature ledger in `PROGRESS.md` with supported options, evidence, deliberate differences, and remaining gaps. Preserve the original Laravel reference items unless completion-state changes are explicitly justified. Keep pending/partial/excluded distinct from completed.
5. Follow the project-local progress-graph skill: regenerate artifacts and run graph freshness, the full Bun tests, typecheck, and whitespace checks. A failed or skipped test is not verification.
6. Update the backlog and this checkpoint with the next work and actual validation results. Do not report total completion until all applicable entries have evidence and no unresolved blockers are hidden.
7. Start the next bounded workflow. Workflow completion notifications are the primary wake signal; a long dynamic-loop fallback keeps the task scheduled if a notification is lost. Do not poll background agents.

## Completion rules

- A command's existence/help is not equivalent to its backend being implemented.
- Generating a class is distinct from implementing the queue/router/event/mail/provider subsystem that consumes it.
- Unit/mock/offline SQL evidence is distinct from real-process or live-service evidence.
- External PostgreSQL/MariaDB validation stays blocked until authorized disposable services are available; work on other independent features can continue.
- Never bypass a permission denial. Record the blocker and request user action if necessary.
- The loop runs only while the session/runtime is available. Do not promise perpetual execution across session closure or claim unattended work that did not run.
