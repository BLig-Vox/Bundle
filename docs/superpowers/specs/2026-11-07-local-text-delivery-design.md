# Explicit local text-mail and notification delivery

## Intent and chosen approach

Continue the standing implementation directive with consumed `make:mail` and `make:notification`, not decorative classes. Use existing Bun/TypeScript and no new packages, network services, markup or ORM tables. This is a leader-selected bounded implementation choice under the user's instruction to continue without further questions; it is not separately claimed human design approval.

Alternatives: injectable-only transports would prove dispatch but provide no usable default persistence; external SMTP would need service/credential/live-test authorization. Implement an explicitly selected private local JSON outbox plus injectable transport. Local acceptance is not delivery to an inbox or external SMTP parity.

## Contracts

- `src/mail/mail.ts`: `MailMessage {to: readonly string[]; subject: string; text: string; from?: string; replyTo?: string}`; `MailReceipt {id:string; accepted:true}`; `MailTransport.send(message:MailMessage, options?:{signal?:AbortSignal}):Promise<MailReceipt>`; `Mailable.build():MailMessage|Promise<MailMessage>`; `sendMail(transport,message,options?)` and `sendMailable(transport,mailable,options?)` validate, snapshot and cooperatively check cancellation around awaits. No missing/disabled transport successful no-op.
- `validateMailMessage(unknown):MailMessage` returns a copied/frozen closed plain-data shape. Limit32 recipients, addresses320 UTF-8 bytes, subject998 bytes and nonempty, text64KiB, whole message128KiB. Conservative ASCII single-mailbox grammar, no display names/headers; reject C0/DEL in address/subject, unpaired surrogates everywhere and NUL in text. Text is plain text, never interpreted as markup. Lossless values or refusal, never redaction/truncation.
- `src/mail/outbox.ts`: `LocalOutboxMailTransport(root)` explicitly receives an absolute canonicalizable root; send validates even when called directly. Version1 closed JSON records `{version:1,id,createdAt,message}` at `.bundle-mail/outbox/<uuid>.json`; create-only atomic publication using private synced temp and exclusive hard-link publication. Fixed paths, private0700 directories and0600 single-link regular files, owner/identity checks, bounded fatal UTF-8 reads, generic errors. Existing unsafe state is preserved. `list({limit?:number})` returns bounded metadata only `{id,createdAt,recipientCount}`; `read(id)` is explicit raw-content inspection. No replay/clear CLI, automatic retention, queue, retry or overwrite. Hostile concurrent tree rename outside guarantee.
- `src/notifications/notification.ts`: `Notification.toMail(recipient:string):MailMessage|Promise<MailMessage>` and `notifyMail(transport,notification,recipient,options?)`; explicit mail-channel adaptation using the same validated transport. No automatic identity, database table, event registration, multi-channel dispatch or persisted notification history.
- Generators emit runnable explicit example classes at `src/mail/<namespace>/<Name>.ts` and `src/notifications/<namespace>/<Name>.ts` with computed aliased type imports. Mail build uses `recipient@example.invalid`; notification toMail uses the explicit recipient parameter. No send at import/construction. Custom consumed `mail.ts.stub` and `notification.ts.stub`, existing exclusive/no-symlink rules and name collision coverage;20 total templates.

## Evidence and boundaries

Tests use unique disposable roots only, never real `.env`, databases or recipients. Verify actual generated CLI modules delivered through an explicit local outbox in separate processes; private permissions, canonical aliases, strict bounds/shapes, sensitive error suppression, corrupt records, symlink/hardlink preservation, cancellation and concurrent create-only writes. No network imports or calls. Independent review and full suite/types/graph/provenance precede inventory credit. Mail acceptance is only durable local persistence; notification credit is only an explicit local text-mail adapter, never external delivery or ORM notifications tables.
