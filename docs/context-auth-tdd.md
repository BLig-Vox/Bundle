# Request context and Notes middleware: test-first evidence

Before implementation, `bun test src/web/context.test.ts` failed with `Export named 'createContextKey' not found`. The actual generated-manifest test (`bun test src/cli/apps.test.ts -t 'generated auth and Notes flow'`) failed expecting 401 but receiving 400: unauthenticated Notes POST still parsed JSON before authentication. A scaffold regression then failed because generated structural Route types omitted context.

The context tests cover invariant branded symbol keys, inferred reads including absence, rejected wrong value/key types, symbol identity, deletion, concurrent and repeated dispatch isolation, middleware-to-handler state, early denial, registration snapshots, repeated next and error sanitization. Existing middleware tests retain ordering, concurrent next, safe errors, HEAD, security and method coverage.

Generated Notes explicitly mounts requireAuth in the actual manifest. It checks POST Origin before token parsing or SQLite lookup, resolves an existing live session, and sets exactly one typed key containing a numeric user ID. The handler only consumes that ID and gets an ORM owner reference. Direct handler calls without context fail closed. Auth endpoints retain their public/endpoint-specific policies.

Generated auth/Notes tests use createRoutes(env) from the actual manifest with isolated SQLite. Direct Auth tests and Notes body-parser checks remain. Middleware tests observe all context writes and verify exactly the user ID is stored, never session IDs/tokens, including denial and expiry. The CLI app test loads the unchanged manifest through createRouteHandler before migrations, proving missing-auth GET/POST return 401 and invalid Origin returns 403 even with a syntactically valid cookie and an unavailable session table. It also runs migration, registration, rotation, Notes persistence and logout through that manifest. Existing generated ownership/expiry tests now also use the manifest factory. Installed-app acceptance copies context compile/runtime assertions through the generated adapter.
